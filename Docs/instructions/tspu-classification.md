# Полная классификация ТСПУ

Это отдельная диагностика по каноническому корпусу **tspu-class-test v2.9**: 34 стратегии, отдельно TLS 1.2 и TLS 1.3. Она не заменяет быстрый подбор и не применяет победителя автоматически.

## OpenWrt / LuCI

Откройте **Службы → OWS → Zapret → Версия 2 → Конструктор пресетов → Классификация ТСПУ**. Укажите домен, 1–5 повторов и ожидание 2–30 секунд. IPv6 включается только при рабочей глобальной IPv6-связности.

MAIN zapret2 останавливается на время этого теста и восстанавливается после завершения или кнопки **Остановить и восстановить MAIN**. Не запускайте параллельно другие проверки: общий lock также останавливает запуск автоподбора.

По SSH:

```sh
/root/zapret2-tools/strategy-check-control.sh classify_start www.youtube.com 3 2.5 0
/root/zapret2-tools/strategy-check-control.sh classify_status
/root/zapret2-tools/strategy-check-control.sh classify_stop
```

Последний аргумент запуска: `0` — только IPv4, `1` — дополнительно IPv6. Отчёты находятся в `/tmp/class_report.txt`, `/tmp/tspu_test_run.log` и `/tmp/class_test.log.short` и очищаются при перезагрузке.

## Конструктор восстановления пресета

В разделе **Восстановление профилей** можно превратить результаты в узкие профили-кандидаты:

1. Сначала выполните healthcheck и полную классификацию нужного домена.
2. **Показать план восстановления** использует только повторные сбои и строки, стабильные на TLS 1.2 и TLS 1.3.
3. **Создать выключенных кандидатов** выполняет dry-run, но не перезапускает MAIN и не меняет старые профили.
4. **Проверить кандидатов** выполняет по два подтверждения на каждой версии TLS без остановки MAIN.
5. **Применить проверенных кандидатов** доступно только после проверки. Если цель уже работает или маршрут изменился, применение отклоняется. После рестарта проверяются цели и ранее исправные сайты; при сбое выполняется откат.

Кандидаты ограничены конкретным `--hostlist-domains`, поэтому одна удачная цепочка не становится глобальным правилом для всех сайтов. Конструктор не работает по cron и не запускает полный классификатор автоматически.

## DNS-диагностика и обучение

В **Zapret2 — Конструктор** есть отдельный DNS-блок. Текущий DoH остаётся upstream; DNS-ответы не переписываются.

- Диагностика сравнивает ответ текущего dnsmasq с прямым Google DoH-запросом.
- Обучение наполняет только отдельные `learning4/learning6` в таблице `zapret2_dns`, не меняя активные профили и `ipset-all`.
- Перенаправление внешнего UDP/TCP DNS из `br-lan` включается отдельной кнопкой. Локальные адреса, клиентский DoH и DoT 853 не перехватываются.
- Исключения `/ru/`, `/su/` и fallback текущего DoH сохраняются. Изучение IP не доказывает его доступность: healthcheck всё равно необходим.

Для обучения требуется `dnsmasq-full`. Диагностика и перенаправление не включают DNSSEC и не меняют DHCP-настройки.

## Windows

В `service.bat` выберите **9. Blockcheck**, затем режим **c**. Либо из консоли администратора:

```bat
python blockcheck.py www.youtube.com --classify --repeats 2 --timeout 8
```

Служба zapret2 восстанавливается, только если была запущена до теста. Отчёт сохраняется в `logs\tspu_class_ДАТА.txt`. Не используйте `taskkill` или `Stop-Process` для winws2: временный движок должен завершиться через CTRL_BREAK.

## Как читать результат

- **stable** — все попытки строки прошли; **flapping** — прошла только часть; **slow** — данные пошли, но не загрузились за отведённое время.
- **L0-** — нарезка работает без фейков; **L0** — работает обратный порядок; **L2** — нарезке нужен фейк.
- **Аномалия** — работает прямой split/seqovl; **особый** — голый fake, SLD-разрез или новые механики.
- **incompatible/error** — локальная ошибка или отсутствующая функция движка, а не доказанный ответ ТСПУ.

Для каждой версии TLS выводится отдельная рекомендация. Скопируйте её в отдельный профиль и проверьте вручную. Короткая curl-проба не эквивалентна браузеру, QUIC или длинному видеопотоку; для YouTube полезен отдельный свежий узел `googlevideo.com` и реальное воспроизведение.
